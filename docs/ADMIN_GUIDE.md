# Правила внесения данных в таблицу (для админов)

Этот документ описывает, как корректно заполнять Google-таблицу, из которой автоматически синхронизируется сайт.  
Нарушение правил → синк падает с ошибкой → сайт продолжает показывать старые данные (и создаётся Issue).

---

## 1. Структура книги

Книга состоит из **двух вкладок** (листов):

| Вкладка | Назначение | Заголовок (первая строка) |
|---|---|---|
| `systems` | Звёздные системы / картографические группы | `id,name,x,y,faction,description,source_url` |
| `places` | Места: планеты, луны, астероиды, станции, платформы, прочее | `id,name,type,system_id,x,y,faction,description,source_url` |

**Не добавляйте лишние колонки, не меняйте порядок, не добавляйте строки-заголовки внутри данных.**

---

## 2. Правила для вкладки `systems`

| Колонка | Тип | Обязательна | Правила |
|---|---|---|---|
| `id` | текст | да | Уникальный идентификатор системы. Латиница, цифры, дефисы. Пример: `korhal`, `tarsonis-system`. **Не повторяется.** |
| `name` | текст | да | Отображаемое имя. Можно на русском. |
| `x`, `y` | число | да | Координаты узла на карте. Целые или дробные. Диапазон: 0..10000 (по размеру карты). |
| `faction` | текст | нет | Фракция. Пример: `Доминион`, `Зерги`. |
| `description` | текст | нет | Описание. Можно многострочный (переносы строк допустимы, но без запятых-разделителей внутри — см. §6). |
| `source_url` | текст/URL | нет | Ссылка на источник (Wiki и т.п.). |

---

## 3. Правила для вкладки `places`

| Колонка | Тип | Обязательна | Правила |
|---|---|---|---|
| `id` | текст | да | Уникальный идентификатор места. Пример: `tarsonis`, `aiur-moon-1`. **Не повторяется** (в рамках places). |
| `name` | текст | да | Отображаемое имя. |
| `type` | enum | да | Одно из: `planet`, `moon`, `asteroid`, `station`, `platform`, `other`. |
| `system_id` | текст | нет | ID системы-владельца (должен существовать в `systems.id`). Пусто — место «свободное». |
| `x`, `y` | число | нет | Собственные координаты. Если пусто — берутся из системы (`system_id`). |
| `faction` | текст | нет | Фракция. |
| `description` | текст | нет | Описание. |
| `source_url` | текст/URL | нет | Ссылка на источник. |

### «Уникальные» места (станции, пояса астероидов)
- `type` = `station` / `asteroid` / `platform` / `other`, `system_id` заполнен.
- В каталоге попадают в раздел **«Иные места» (ETC)**, но в досье системы показываются как её члены.
- Координаты можно оставить пустыми — унаследуются от системы.

---

## 4. Координаты

- Система координат: **пиксельная, Y вверх** (как на карте). Если ваш источник даёт Y вниз — преобразование `flipY` настраивается в `data/sources.json` (делает разработчик), **не правьте таблицу руками**.
- Диапазон: `0 ≤ x ≤ 10000`, `0 ≤ y ≤ 10000` (по размеру карты). Координаты вне диапазона → синк падает.
- Дробные значения допустимы (разделитель — точка: `123.45`).
- Пустые `x`/`y` у места допустимы только при заполненном `system_id`.

---

## 5. Связи system ↔ place

- `places.system_id` должен ссылаться на существующий `systems.id`.
- Одна система может иметь много мест.
- Место может быть без системы (`system_id` пусто) — тогда координаты `x`,`y` обязательны.
- Удалять систему, на которую ссылаются места — нельзя (синк не проверяет FK сейчас, но фронт покажет «система не найдена»).

---

## 6. Формат CSV / Google Sheets

- Таблица должна быть **опубликована**: File → Share → Publish to web → CSV (отдельно для каждой вкладки).
- Разделитель — запятая. **Не используйте запятые внутри полей** (они сломают CSV). Если нужна запятая в описании — замените на `;` или перенос строки.
- Кодировка — UTF-8 (Google Sheets отдаёт UTF-8 по умолчанию).
- Первая строка — строго заголовки, без пустых строк перед ними.
- Пустые строки в конце — допустимы (синк их отбросит), но лучше не оставлять.
- Не добавляйте колонку-метку (например, «Системы:») — она станет лишним столбцом.

---

## 7. Валидация (что проверяет синк)

1. Файл не пустой.
2. Заголовки присутствуют.
3. `id` уникален (в рамках листа).
4. Координаты в пределах 0..10000 (если заданы).
5. Обязательные колонки на месте.

При провале валидации **рабочие файлы не затираются** — сайт продолжает жить на последних хороших данных, а вам приходит Issue + (если настроен) Discord-алерт.

---

## 8. Чего делать нельзя

- ❌ Менять порядок колонок или удалять заголовки.
- ❌ Дублировать `id`.
- ❌ Вставлять запятые внутри полей.
- ❌ Оставлять `system_id` ссылку на несуществующую систему.
- ❌ Публиковать всю книгу целиком («Entire document») — публикуйте каждую вкладку отдельно.
- ❌ Менять `id` существующего объекта — это создаст новую запись и потеряет старую.

---

## 9. Как добавить новое место

1. Откройте вкладку `places`.
2. Добавьте строку: `id,name,type,system_id,x,y,faction,description,source_url`.
3. Если место привязано к системе — укажите `system_id` и можно оставить `x`,`y` пустыми.
4. Опубликуйте вкладку (если автопубликация включена — изменения подхватятся сами при следующем синке).
5. Дождитесь синка (раз в 6 часов) или запустите вручную: Actions → Sync upstream map data → Run workflow.

---

## 10. Быстрая проверка перед публикацией

- [ ] Заголовок точно совпадает с шаблоном.
- [ ] Все `id` уникальны.
- [ ] Координаты в диапазоне 0..10000.
- [ ] `system_id` ссылается на существующую систему.
- [ ] Нет запятых внутри полей.
- [ ] Вкладка опубликована (открывается ссылка `pub?output=csv`).
