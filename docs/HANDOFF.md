## 2. Как устроен репозиторий

```
site/                  ← корень публикации (это и есть корень сайта)
├── index.html         карта галактики, открывается по /
├── galaxy.js  galaxy.css  galaxy-fx.js  galaxy-ping.js
├── sector/sector.html
├── minimal/minimal.html + minimal-skin.css
└── shared/            app.js, links.js, timeline-loader.js + все общие CSS

data/                  CSV и JSON; пишут tools/sync.py и tools/build_assets.py
assets/src/            ИСХОДНИКИ картинок (в Git, в веб не публикуются)
assets/                собранные тайлы и WebP (Git-ignored, собираются при деплое)
docs/, tools/, .github/ — служебное
```

- Все внутренние ссылки от корня сайта: `/shared/…`, `/sector/sector.html`, `/data/…`, `/assets/…`.
- Деплой: `pages.yml` → `pip install pillow` → `tools/build_assets.py` → копирует `site/`, `data/`, `assets/`
  (минус `assets/src`) в `.publish` → `upload-pages-artifact`.
- **Pages настроен как GitHub Actions** (пользователь переключил в Settings). Если вернуть
  «Deploy from a branch», публиковаться будет корень репозитория через Jekyll и всё сломается.
- Данные: `tools/sync.py` каждые 6 ч тянет две таблицы Google Sheets из `data/sources.json`.

## 3. Что сделано по частям

**Картинки и тайлы (главное).** Исходник карты сектора 10 000×10 000 → пирамида WebP 512×512:

| Уровень | Размер | Тайлов | Вес |
|---|---|---|---|
| 0 | 1250² | 9 | 120 КБ |
| 1 | 2500² | 25 | 312 КБ |
| 2 | 5000² | 100 | 852 КБ |
| 3 | 10 000² | 400 | 2.5 МБ |

Грузится только видимое: на стартовый вид 9 тайлов ≈ 120 КБ. Манифест `assets/tiles.json`
(`dir`, `levels`, `version`, `preview`), подложка `map-preview.webp` 2500².
Логотип 2.08 МБ → 32 КБ, карта галактики 6.85 МБ → 256 КБ (+ 1200 px под `srcset`),
макеты → по 5 КБ. Вес первой загрузки: главная 9.22 МБ → ~0.45 МБ, сектор 2.29 МБ → ~0.35 МБ.
Подложка больше не тянется с Google Drive (`links.js` → `sectorMapPreview: ''`).

**Версии.** Манифест несёт `version` = первые 8 символов SHA-256 исходника карты
(сейчас `17b60184`); `app.js` добавляет `?v=` к адресам тайлов и подложки. Ссылки на
`galaxy-map-*`, логотип и макеты получают `?v=0f419d0e` — общий хэш всех исходников,
их расставляет сам `build_assets.py` (шаг «Версии в ссылках»), `--check` следит за свежестью.
Pages кэширует файлы на 10 минут, без версий после пересборки часть посетителей видела бы старое.

**Каталог.** Места без колонки `type` теперь попадают во вкладку «Места» (раньше получали
`other`, который не совпадал ни с одной вкладкой — место было в данных, но не показывалось).
`platform` и `other` тоже не совпадали ни с одной вкладкой — исправлено; `PLACE_TYPES`
дополнен метками для всех шести типов; чипы фильтра строятся для всех типов, но только
для тех, что есть в данных.

**Прелоадер.** Искусственная пауза 1.9 с убрана, экран уходит после первой отрисовки canvas.
Логотип загрузки — с `rel="preload"` и `fetchpriority="high"`, то есть первым в стеке.

**Синк.** Если вместо CSV приходит HTML (таблицу перестали публиковать в интернете),
`sync.py` падает с понятной ошибкой, а не записывает страницу входа в `data/*.csv`.

## 4. Заблокировано пользователем

1. **Таблица Google Sheets не опубликована в интернете.** Оба URL из `data/sources.json`
   сейчас отдают страницу входа. Нужно: Файл → Поделиться → Опубликовать в интернете → оба
   листа → CSV. Если ключ `/e/2PACX-…` изменится — обновить `url` в `data/sources.json`.
   Доступа «по ссылке» недостаточно: серверу нужен гостевой доступ.
2. **В листе `places` нет колонки `type`.** Код теперь не ломается и без неё, но по
   `docs/ADMIN_GUIDE.md` значения должны быть: `planet`, `moon`, `asteroid`, `station`,
   `platform`, `other`. Текущий заголовок: `name,ID,system_id,x,y,faction,description,source_url`.
3. **Координаты тестовые.** В `data/systems.csv` Корхал `1.0/1.0`, Авернус `2.0/2.0`.
   Пространство растра — 0…10 000. Совпадение подложки с маркерами никто глазами не проверял.
4. **Исходник карты заливается вручную** в `assets/src/koprulu-sector.jpg` (решено пользователем).
   После замены файла и пуша тайлы пересоберутся сами — по SHA исходника.

## 6. Следующая задача пользователя — анимация

Пользователь собирается **заменить анимацию** на карте галактики — переход при выборе
сектора на текущем приближении и фокусировке. Задача ещё не сформулирована; на момент
написания конспекта он уточнял, может ли агент смотреть скриншоты.

Где смотреть:

| Файл | Что там |
|---|---|
| `site/galaxy.js` | зум и фокус: `animateTo`, `fitView`, `zoomAt`, `clampView`, `clampAxis`, `easeOutCubic`; переход на страницу сектора — `GalaxyPing.start({… onEnd: function () { window.location.href = href; }})` около строки 767; то же для ОЗД — строки 925 и 1045; экран загрузки (консоль) — 8 с на десктопе, 2 с на мобильных, `BOOT_TICK_MS = 16` |
| `site/galaxy-ping.js` | рамка захвата: `STAGE_COUNT = 9`, `STAGE_STEP = 150` мс, `STAGE_LEN = 130` мс, `OUTER_GAP = 18` px, `OUTER_TURN = π/6`, `OUTER_ARM_K = 0.5`, `OUTER_TAIL_MAX = 22` px; API `GalaxyPing.start / refresh / stop`; элемент затемнения `.target-dim` создаётся здесь же |
| `site/galaxy-fx.js` | 240 полос поверх картинки, глитч/волна/линии; rAF останавливается в покое, уважает `prefers-reduced-motion` |
| `site/galaxy.css` | `.target-dim`, `.galaxy-stage.is-zooming`, `.map-fx`, `.map-fx-band`, хотспоты `.target-*` |
| `site/index.html` | хотспоты с `data-cx`, `data-cy`, `data-size`, `data-name`, `data-macket`; `#galaxyMap` с `srcset` |

Важно: анимация должна работать при **текущем** приближении и фокусировке — то есть
зависеть от состояния вида (`state.view.scale/tx/ty` в `app.js`, локальные переменные вида
в `galaxy.js`), а не от фиксированных пикселей.

## 7. Инфраструктурные грабли

- **Снапшот теряет бинарники.** Между сессиями `assets/src/` (30 МБ) и собранные
  `assets/tiles/` исчезали, а указатель ветки откатывался на `main`. Лечится:
  `git fetch -q origin <ветка> && git reset --hard FETCH_HEAD`, затем
  `pip install --break-system-packages pillow` и `python3 tools/build_assets.py`.
  Сборка детерминирована — версии `?v=` совпадают, правок в файлах не появляется.
- **jsdom не умеет canvas**, и `app.js` на этом останавливается — без подмены контекста
  прогон проверяет только загрузку, а не сам атлас. Стенд лежит в `/home/user/smoke2`
  (вне репозитория, не сохраняется): `mkdir -p /home/user/smoke2 && cd /home/user/smoke2 &&
  npm init -y && npm i jsdom`. Там `run.js` подменяет `getContext` прокси-заглушкой и
  подсовывает данные через `window.__MAP_DATA__`, собранные из `data/systems.csv` и
  `data/places.csv`. Плюс `matrix.js` — матрица «тип места → вкладка».
- **Сеть ограничена**: `github.com`, `codeload.github.com`, `api.github.com`,
  `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`. До боевого сайта из bash не
  достучаться; `fetch_page` открывает HTML, но на `.csv`/`.json` отдаёт 500.
- **Права токена**: нельзя менять настройки Pages (403) и нельзя запускать
  `workflow_dispatch` (403). Деплой происходит только пушем в `main`, то есть мержем PR.
- **В Git — только исходники.** `assets/tiles/`, `assets/tiles.json`, `assets/map-preview.webp`
  и собранные `*.webp` в `.gitignore`; не коммитить их.
- `data/meta.json` пишут два скрипта: `sync.py` (источники, sha, размеры) и
  `build_assets.py` (`mapSize`, `assets.hasRaster`, версии). Ключи друг друга они не затирают.

## 9. Правила пользователя

- Комментарии, тексты интерфейса и сообщения коммитов — **по-русски**.
- `sector.html` и `minimal.html` держать в синхроне: любая общая правка разметки или CSS
  применяется к обоим.
- Работаем только в своей ветке; в `main` не пушим. Путь: правки → коммит → PR →
  пользователь смотрит → `gh pr merge <номер> --merge`.
- Крупные правки показывать до мерджа: агент не видит результат глазами, визуальную
  проверку делает пользователь.
- Коммитить исходники картинок, а не производные файлы.
