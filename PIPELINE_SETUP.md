# Автосинхронизация карты и систем — без Google API

Карта скачивается прямым HTTP-запросом через `gdown`, а таблица систем читается как **опубликованный CSV**. Ни OAuth, ни API-ключ, ни service account не нужны. Браузер сайта к Google не обращается вообще: к моменту публикации карта уже нарезана в тайлы, а таблица превращена в `data/system-overrides.json`.

> **Условие для карты:** файл в Drive должен открываться без входа в Google — доступ **Anyone with the link / Все, у кого есть ссылка → Viewer / Читатель**. При режиме Restricted прямая загрузка не сработает.
> `gdown` понимает обычные share-ссылки и страницу подтверждения для больших файлов: [gdown](https://github.com/wkentaro/gdown).

## Что делает workflow

`.github/workflows/sync-and-deploy.yml` запускается вручную, по расписанию (cron в UTC) и при изменениях файлов сайта:

| Шаг | Инструмент | Результат |
|---|---|---|
| Сверить Wiki-каталог | `tools/sync_starcraft_wiki.py`, `tools/sync_starcraft_wiki_places.py`, `tools/derive_catalog.py` | полный строгий реестр 297 мест: планеты, луны, астероиды, станции/платформы |
| Проверить оригинальный список | `tools/audit_original_google_doc.py` | 317 строк Google Doc → 316 уникальных legacy-записей; проверка системных оснований |
| Скачать полную карту | `tools/download_drive_file.py` | временный `assets/_source/koprulu_map.jpg` на runner |
| Проверить местоположения | `tools/verify_overrides_on_map.py` + Tesseract `rus+eng` | OCR-проверка 25 подписей; полный тайловый поиск при `--locate` |
| Собрать всю пирамиду | `tools/build_tiles.py` | временные `assets/tiles/`, `assets/tiles.json`, `assets/map-preview.webp` |
| Синхронизировать таблицу | `tools/sync_system_overrides.py` | временный `data/system-overrides.json` в сборке |
| Проверить данные | `tools/validate_data.py` | ошибки останавливают публикацию |
| Собрать Pages | `tools/set_asset_version.py`, `tools/build_single_file.py`, `tools/stage_pages.py` | временный каталог `dist/` |
| Опубликовать | `actions/deploy-pages` | Pages artifact без коммита сгенерированных файлов |

Ни исходная карта, ни тайлы не попадают в Git: они существуют только на временном runner и внутри опубликованного Pages artifact.

## 1. Карта в Google Drive уже настроена

Рабочий источник записан в `data/sources.json`:

```text
https://drive.google.com/file/d/1j9FL3Pd8vSRsw_D-R4SQuAV3Ufxhf7Dc/view?usp=sharing
```

Файл проверен: публично скачивается через `gdown`, фактический формат JPEG, размер **10000×10000**, объём 22 749 370 байт. Workflow вызывает downloader без аргумента — тот берёт ссылку из `data/sources.json`.

Для замены карты: загрузите квадратный PNG / JPEG / WebP; включите **Anyone with the link → Viewer**; проверьте ссылку в инкогнито; затем замените `map.url` в `data/sources.json`. Альтернатива — Repository variable `GOOGLE_DRIVE_MAP_URL`: она имеет приоритет и позволяет подменить URL без изменения файла. [Справка Google Drive](https://support.google.com/drive/answer/2494822?hl=en&co=GENIE.Platform%3DDesktop).

**Важно:** режим «Все, у кого есть ссылка» разрешает скачать исходник карты каждому, у кого есть ссылка. Не используйте его для приватных материалов.

## 2. Подготовьте таблицу систем

1. Импортируйте `data/systems-sheet-template.csv` в Google Sheets.
2. Не удаляйте колонку `id`: это стабильный ключ. Переименование системы меняет только отображаемое название — строка остаётся привязанной к записи каталога.
3. Заголовки: `id`, `Название системы`, `X`, `Y`, `Описание`, `Фракция`.
   - `X` и `Y` — целые от **0 до 10000**; альтернатива — `x_norm` / `y_norm` в диапазоне **0…1**.
   - Заполняйте X и Y вместе либо оставляйте обе ячейки пустыми: пустая пара не удаляет координату.
   - Пустые описание и фракция не создают переопределение; заполненная фракция участвует в фильтре.
   - В шаблоне 55 строк; координаты стоят только у 25 систем, снятых с подписей карты. Для остальных оставляйте X/Y пустыми — условные и отсутствующие точки не стоит выдавать за измеренные.
4. **Файл → Поделиться → Опубликовать в интернете** → нужный лист → формат **CSV** → **Опубликовать** → скопируйте ссылку. [Инструкция Google Sheets](https://support.google.com/docs/answer/183965?hl=en&co=GENIE.Platform%3DDesktop).
5. Вставьте ссылку в variable `GOOGLE_SHEETS_CSV_URL`. Публикуйте только то, что можно показывать: CSV доступен всем по ссылке.

Проверить таблицу можно локально, без сети:

```bash
python3 tools/sync_system_overrides.py --csv data/systems-sheet-template.csv --dry-run
```

Строка с неизвестным `id`, дубль, координата вне диапазона или половинчатая пара X/Y **останавливают** синхронизацию: лучше не применить строку, чем поставить случайную точку.

## 3. GitHub Variables (карте не обязательны)

В вашем репозитории откройте **Settings → Secrets and variables → Actions → Variables → Repository variables**:

| Name | Что вставить |
|---|---|
| `GOOGLE_DRIVE_MAP_URL` | необязательная подмена `data/sources.json`; без неё используется уже записанная Drive-ссылка |
| `GOOGLE_SHEETS_CSV_URL` | CSV-ссылка из «Опубликовать в интернете» |

Секреты не нужны: `GOOGLE_SERVICE_ACCOUNT_JSON`, API-ключи и OAuth не используются. Карту workflow скачивает даже без variables; без `GOOGLE_SHEETS_CSV_URL` пропускается только синхронизация таблицы.

## 4. Включите Pages и запустите Action

1. В вашем репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Убедитесь, что основная ветка называется `main` (иначе поправьте `push.branches` в workflow).
3. Запись в репозиторий workflow не нужна: ему достаточно `contents: read`, `pages: write`, `id-token: write`, уже заданных в YAML.
4. Отправьте файлы в репозиторий и запустите **Actions → Sync and deploy Koprulu Atlas → Run workflow**.

Дальше workflow идёт по расписанию; для немедленной синхронизации нажимайте **Run workflow**. Google может обновлять опубликованный CSV с задержкой — Action увидит новую версию при следующем чтении.

## Что обновляется автоматически

- MediaWiki API заново перечисляет планеты, луны, астероиды и станции/платформы; строгая политика канона формирует 297 мест, а явные `WorldBox.system` имеют приоритет над прежней группировкой.
- Полный Drive-файл скачивается на runner; его SHA-256 печатается в логе.
- Tesseract (`rus+eng`) сверяет 25 опубликованных координат с подписями именно этой карты; при совпадении менее 80% публикация останавливается.
- Временно строятся все 534 тайла четырёх LOD и `assets/map-preview.webp`; `data/meta.json` внутри сборки получает `assets.hasRaster = true`.
- Таблица временно превращается в `data/system-overrides.json`: название, X/Y, описание и фракция накладываются по `id`.
- Cache-busting пересчитывается, затем собирается и публикуется Pages artifact.
- После deploy runner удаляется. В ветке репозитория карта, тайлы и сгенерированные JSON не появляются.

Локальные правки в `localStorage` остаются личным слоем поверх опубликованной таблицы. Если в браузере есть старые правки, сбросьте их в панели администратора.

## Если не скачивается

- Лог сообщает `download() got an unexpected keyword argument 'fuzzy'` — в репозитории старая версия `tools/download_drive_file.py`; замените её актуальной. Это ошибка совместимости `gdown`, а не доступа к файлу.
- Ссылка не открывается в инкогнито — исправьте общий доступ (роль Viewer), особенно если аккаунт Workspace запрещает публичные ссылки.
- Проверьте, что это **файл**, а не папка, и что загружен обычный PNG/JPEG/WebP, а не Google Docs или PSD.
- `gdown` пишет «файл не найден / доступ закрыт» — доступ не публичный. Приватный файл без авторизации (Drive API или service account) скачать нельзя.
- CSV не читается — убедитесь, что ссылка ведёт на **опубликованный CSV**, а не на страницу редактирования; проверьте, что в таблице есть заголовок `id`.
- Сборка тайлов упала с сообщением про квадрат — карта неквадратная; приведите холст к квадрату или запустите с `--force`, если искажение допустимо.
- `Failed to get ID Token`, `actions-run-service`, HTTP 500 — сборка уже готова, упал сервис OIDC GitHub. Workflow использует отдельный deploy-job, актуальный `deploy-pages@v5.0.1`, job-level `pages: write` / `id-token: write` и пять проверок OIDC с задержкой. Сначала нажмите **Re-run failed jobs**. Если переменные OIDC отсутствуют, проверьте **Settings → Pages → Source: GitHub Actions**; если endpoint продолжает отдавать 500, это временный сбой GitHub Actions.
- Если deploy не стартует вообще — проверьте, что Pages использует источник **GitHub Actions**. Запись workflow в `main` не требуется.
