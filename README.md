# Koprulu Sector Atlas

Интерактивный статический атлас сектора Копрулу: **297 строго канонических индивидуальных мест** и **55 системных/картографических групп**, наложенные на растровую карту **10000 × 10000 px**. В главный реестр входят 177 планет, 38 лун, 8 астероидов и 77 станций/платформ; три страницы имеют по два типа, поэтому сумма типовых членств равна 300. Карта автоматически загружается из публичного Google Drive; рабочая ссылка хранится в `data/sources.json`.

Интерфейс не требует внешних библиотек, шрифтов или API: canvas-рендер тайлов с уровнями детализации, поиск, каталог, досье и режим правки координат работают из обычной статики. Wiki API используется только сборочным скриптом полного канонического аудита. Исходный локальный каталог из 316 строк сохранён как `data/legacy-planets.json` и не смешивается с главным строгим реестром.

## Что есть на странице

- **Timeline Project UI** по предоставленному логотипу: графитово-чёрный фон, бирюзовая навигационная сетка, приборные кольца, технические панели и короткий экран `AUTHENTICATING…` примерно на две секунды. При ошибке инициализации лоадер снимается автоматически.
- **Карта** с плавным масштабированием: колесо мыши, pinch, перетаскивание, `+` / `−` / `0`, двойной щелчок — приближение в точку.
- **Маркеры систем.** Сплошное кольцо с крестовиной — координата снята с подписи на карте (25 систем). Пунктирное кольцо — условная точка (19 систем); 11 систем без надёжной координаты не рисуются. Зелёный маркер — ваша локальная правка. Круги, крестовины, hit-area и подписи растут в мировом масштабе вместе с растром, но имеют читаемые min/max и collision-aware LOD.
- **Слой подписей карты** (`data/map-labels.json`, 221 точка): крестики там, где карта реально что-то называет. Подписи подмешиваются в подсказки поиска и не засоряют обзор — OCR-шум показывается только при сильном увеличении.
- **Поиск** по местам, системам и подписям карты: нечёткий, терпит падежи и опечатки, `/` — фокус.
- **Каталог** слева: функциональные разделы «Системы», «Планеты», «Станции», «Платформы» и «Иные места» (луны и астероиды), связанные с реальными фильтрами данных; поиск и переходы из досье автоматически открывают правильный раздел, ниже остаются комбинируемые фильтры по типу и фракции и сортировка.
- **Досье** справа: типы места, места системы, координата с указанием происхождения, ссылки на источники и StarCraft Wiki (EN).
- **Ссылки-якоря**: `#/s/aiur-system`, `#/p/тарсонис` открывают карточку сразу.
- **Режим администратора**: перетаскивание узлов карты и ручной ввод X/Y с экспортом правок.

## Как запустить

```bash
python3 -m http.server 8080 --bind 0.0.0.0
# http://localhost:8080
```

Внешние библиотеки не нужны. Открывайте через HTTP-сервер, а не `file://`: данные читаются запросами к `data/*.json`, а доступ к файловой системе из `file://` в браузере закрыт.

Если сервер поднять нельзя — откройте `koprulu-atlas.html`: стили, `app.js` и данные вшиты внутрь файла, карта рисуется схемой со слоем подписей.

## Данные

```
data/meta.json                    счётчики, типы мест, размер карты и флаги ассетов
data/systems.json                 55 системных/картографических групп и их строгие члены
data/planets.json                 297 строго канонических мест — основной каталог UI
data/legacy-planets.json          316 прежних обогащённых строк для аудита
data/canonical-wiki-places.json   полный машинный аудит: 297 принятых + 32 исключённых
data/canonical-wiki-places.csv    плоская фильтруемая таблица 297 принятых мест
data/system-overrides.json        25 координат с подписей карты (приоритет над systems.json)
data/map-labels.json              221 подпись карты; системные названия нормализованы
data/systems-sheet-template.csv   шаблон таблицы для синхронизации через Google Sheets
docs/source/original-google-doc.txt       текстовый снимок оригинального Google Doc
reports/starcraft-wiki-canonical-places.md  канонический Wiki-аудит
reports/original-google-doc-reconciliation.md  сверка оригинала, legacy и систем
reports/original-google-doc-reconciliation.csv  построчная таблица всех 316 записей
reports/location-module-recheck.md             проверка OCR-модуля координат и полного поиска
```

Приоритет координат: **локальные правки в браузере → `system-overrides.json` → условная точка из `systems.json`**.

Каталог собирается `tools/derive_catalog.py` из полного Wiki-аудита и материалов в `docs/source/`. Для 191 точного совпадения сохраняются проверенные локальные имена и метаданные; 106 новых мест получают официальный английский заголовок Wiki. Новым местам система назначается только по явному `WorldBox.system`; системные догадки не добавляются.

```bash
pip install -r tools/requirements.txt
python3 tools/sync_starcraft_wiki_places.py  # полный канонический аудит мест
python3 tools/derive_catalog.py              # основной реестр 297 + legacy 316
python3 tools/audit_original_google_doc.py   # сверка 317 строк оригинала и систем
python3 tools/validate_data.py               # id, типы, ссылки, системы и счётчики
```

Снимок аудита: **329 кандидатов**, **297 принятых**, **32 исключённых**, **191 точное совпадение** с прежними строками и **106 новых мест**. Категория сама по себе не доказывает канон: скрипт отдельно исключает cut/beta, Co-op, Heroes, Ghost-only, holiday, concept-only и неподтверждённые RPG/настольные страницы. `Avernus` и `Avernus Station` остаются разными записями.

Оригинальный Google Doc содержит **317 строк объектов / 316 уникальных записей** (`Миранар` продублирован). Legacy-каталог покрывает их полностью. Обновить текстовый снимок и повторить сверку можно командой `python3 tools/audit_original_google_doc.py --refresh`.

Сопоставление подписей карты с каталогом учитывает исходные падежные формы и смешение алфавитов. В производных данных все заголовки систем имеют форму `Система <имя в именительном падеже>`; оригинальная надпись растра сохраняется в `rawMapLabel`. Подписи без пары остаются в слое, их список лежит в `meta.json` (`unmatchedMapLabels`).

## Карта и тайлы

Источник уже настроен в `data/sources.json`:

```text
https://drive.google.com/file/d/1j9FL3Pd8vSRsw_D-R4SQuAV3Ufxhf7Dc/view?usp=sharing
```

Скачать его и собрать пирамиду локально:

```bash
python3 tools/download_drive_file.py --out assets/_source/koprulu_map.jpg
python3 tools/build_tiles.py assets/_source/koprulu_map.jpg
```

Аргумент URL не нужен: downloader сначала проверяет `GOOGLE_DRIVE_MAP_URL`, затем читает `data/sources.json`. Так Repository variable может временно подменить источник, но рабочая ссылка уже находится в проекте.

Скрипт создаёт `assets/tiles.json` (манифест), `assets/tiles/<level>/<col>_<row>.webp` (512 px) и `assets/map-preview.webp`, а в `data/meta.json` ставит `assets.hasRaster = true`. До этого момента страница не запрашивает отсутствующие файлы и рисует схему с сеткой и слоем подписей — атлас полезен и без растровой подложки.

Координаты можно проверить непосредственно по буквам на растре (нужен Tesseract с `rus+eng`):

```bash
python3 tools/verify_overrides_on_map.py assets/_source/koprulu_map.jpg \
  --radii 80,150,300 --json data/map-verification.json
```

Для текущей Drive-карты OCR-проверку прошли **25 из 25** оверрайдов. Ключ `--locate` включает полный поиск переехавшей подписи: карта сканируется перекрывающимися нативными тайлами, текст увеличивается перед OCR, а координата подписи переводится в центр системного кольца. Контрольный тест с намеренно неверной точкой Айура `1000,1000` восстановил правильный центр `6682,5076`.

Центр кольца Редстоуна (`5220, 6133`) подтверждён и увеличенным фрагментом, а подпись `Зигмарис` точно связана со строкой `Сигмарис-Прайм`. Ранее были исправлены две ошибочно сдвоенные пары: Икар/Умоджа и Онуру/Тирадор. Workflow запускает эту OCR-проверку после загрузки Drive-карты и до сборки тайлов.

Неквадратный растр отклоняется: иначе X/Y перестанут совпадать с подписями на карте (`--force`, если искажение допустимо).

## Доступ администратора

Кнопка **«Получить доступ администратора»** открывает форму запроса кода. Код по умолчанию — `koprulu-2513`, он задаётся в `app.js`:

```js
var CONFIG = {
  adminCode: 'koprulu-2513',   // ← замените на свой
  ...
};
```

В режиме правки узлы систем перетаскиваются мышью, X/Y можно ввести вручную (целые 0…10000). Правки сохраняются в `localStorage` браузера, перекрывают опубликованную таблицу и `system-overrides.json`, экспортируются кнопкой **«Экспорт JSON»** в файл, совместимый с `data/system-overrides.json`.

**Ограничение безопасности:** статическая страница не может проверять права — код лежит в браузерном JS и виден любому. Это блокировка интерфейса, а не защита данных. Настоящая авторизация требует серверной проверки; локальные правки к тому же не меняют опубликованную копию сайта.

## Публикация и автосинхронизация

GitHub Action (`.github/workflows/sync-and-deploy.yml`) раз в час и по кнопке:

1. на временный runner скачивает **полный** исходник карты из Drive через `gdown`;
2. OCR-модулем перепроверяет 25 подтверждённых местоположений систем;
3. временно строит пирамиду всей карты: 1250 / 2500 / 5000 / 10000 px;
4. читает опубликованный CSV Google Sheets, если он подключён;
5. проверяет данные, обновляет cache-busting и собирает Pages-артефакт;
6. публикует артефакт и уничтожает runner.

**Карта и тайлы не коммитятся в Git.** В репозитории находятся только код, данные и URL из `data/sources.json`; `.gitignore` блокирует исходник, `assets/tiles/`, манифест и preview. Тайлы существуют только внутри временной сборки GitHub Pages.

`GOOGLE_DRIVE_MAP_URL` — необязательная подмена встроенного URL; `GOOGLE_SHEETS_CSV_URL` нужна только для синхронизации таблицы. Подробности — в [PIPELINE_SETUP.md](PIPELINE_SETUP.md).

## Что было восстановлено

Проект пришёл без `app.js` и остальных инструментов: оставались `index.html`, три CSS-файла, данные и инструкции. Логика интерфейса восстановлена по контракту, который читается в HTML и CSS (`id` элементов, ожидаемые классы, состояния `collapsed` / `wide` / `admin-mode`), а пайплайн — по `README.md` и `PIPELINE_SETUP.md`. Отдельно пришлось исправить то, что мешало другим скинам:

- `minimal-skin.css` тащил на себе интерфейс админ-панели и правки читаемости — они вынесены в `admin-ui.css` и `readability.css` (перенос дословный, см. `tools/split_skin.py`);
- в вики-скине панель каталога стоит за левым краем, поэтому её открытие/закрытие взял на себя `app.js`;
- досье шире прочих панелей и перекрывало кнопки масштаба — положение кнопок пересчитывается при открытии досье;
- `system-overrides.json` содержал две снятые с карты координаты, у которых не было пары в каталоге; они попали в слой подписей, а не в оверрайды.
